## 1. What does NOT work (both refuted with evidence, keep them out of the design space)

**(a) Mirroring the DFlash2 draft model does not fix it.**  Tried: `get_tensor_config()` returns
`MIRRORED` for every tensor a `LLM_ARCH_DFLASH` model with `dflash_selector_rank > 0` owns.  The selector
still aborted at the same place:

```
TODO78-DBG: per-row op TOP_K on 'node_630' [16,2] src0='result_output' [248320,2]
            axis SPLIT_AXIS_0 extents: 124160 124160
```

Reason: the offending tensor is the *target's* `output.weight` (the draft GGUF ships no lm head, so the
draft graph reads the target's).  Its placement comes from the **target's** split policy — the policy is
resolved through the *buffer's* buft device (`ggml-backend-meta.cpp`, the `policy_tensor` branch), and the
target is a `qwen3.8`/27B model whose `output.weight` is `SPLIT_AXIS_1` (vocabulary).  A draft-side policy
change cannot reach it, and mirroring the drafter would cost 1.14 GB/device plus a fully redundant draft
graph for no benefit.

**(b) Demoting the drafter to `-sm layer` while the target keeps `-sm tensor` does not work either.**
`common/speculative.cpp` already has that precedent for a single-device draft (`n_devs == 1`), but pushing
it for every draft aborts at load:

```
pre-allocated tensor (output.weight) in a buffer (Meta()) that cannot run the operation (NONE)
```

i.e. a layer-split draft context cannot read the target's shared embedding/lm-head tensors out of the
target's Meta buffers.  Making it work would mean materialising ~1.4 GB of duplicated shared weights into
the draft's own buffers.

So the logits themselves have to become whole on every device — which is what this change does.

## 2. The design: `GGML_OP_ALL_GATHER`

A new ggml collective whose result is the **whole** input on every backend of a Meta device (a plain copy
on one backend, `GGML_OP_DUP`-equivalent).  In the meta backend the split state is `MIRRORED`, the op is
its own subgraph boundary, the collective runs between the subgraphs, and the node is dropped from every
per-device child graph (the collective fills the tensor; a device-local execution would write only its own
slice).

The gather copies **one "row" at a time** (`ne[1]*ne[2]*ne[3]` rows of `ne0_j` elements): a device's slice
is contiguous in its *own* copy but the destination is the full tensor, where the split axis is the
slowest-varying, so a single `memcpy` per (source, destination) pair would be wrong.  The destination
offsets are the same cumulative per-device extents the canonical host assembly uses in
`ggml_backend_meta_get_tensor_impl` (device order = tensor order; the `rotation` in
`llama_meta_device_get_split_state` only rotates which fraction a device gets, it does not permute the
layout).  Verified byte-exact against `ggml_backend_tensor_get(src)` for `[248320,2]` and `[248320,4]`
tensors (`GGML_META_AG_VERIFY=1` while it existed; the check is not shipped).

Only a plain axis-0 split (`n_segments == 1`, `nr[0] == 1`, contiguous) is implemented; anything else is a
deliberate abort, not a silently wrong gather.  `GGML_META_GATHER_MAX_ROWS` (128) bounds the row batch and
the view pool asserts rather than overrunning.

Files (see `all-gather.patch`):

| file | change |
|---|---|
| `ggml/include/ggml.h`, `ggml/src/ggml.c` | `GGML_OP_ALL_GATHER`, `ggml_all_gather()`, name/symbol tables, `GGML_OP_COUNT` |
| `ggml/include/ggml-rpc.h` | `RPC_PROTO_PATCH_VERSION` 7 → 8 and the count assert (the op enum is on the RPC wire) |
| `ggml/src/ggml-cpu/ggml-cpu.c`, `ggml/src/ggml-cuda/ggml-cuda.cu` | single-backend execution = copy (`dup`), `supports_op`, `n_tasks` |
| `ggml/src/ggml-backend-meta.cpp` | split state, subgraph boundary, the collective, view pool, `supports_op` |
| `src/models/dflash.cpp` | `build_dflash2_selector()` all-gathers `res->t_logits` when the draft is a ≥2-device tensor split |
| `src/llama.cpp` | the r54 rejection is removed (the config is supported now) |
| `src/llama-context.cpp` | see finding F1 below |

The graph-side gate is exact: `model.split_mode() == LLAMA_SPLIT_MODE_TENSOR && model.devices.size() == 1
&& model.devices[0].is_meta` (`devices` holds the meta wrapper itself for a ≥2-device tensor split; a
tensor split over one device skips the wrapper).  `-sm layer` and single-device graphs never build the op,
so their graphs are untouched.

## 3. Findings for the maintainer

**F1 (fixed here, needed for any DFlash drafter under `-sm tensor`).**  `llama_context::extract_layer_inputs`
takes a "device" path that allocates the per-layer F1 buffers with
`ggml_backend_alloc_ctx_tensors_from_buft(..., ggml_backend_get_default_buffer_type(backend))` and then
copies with one pointer range (`ggml_backend_tensor_copy_async(backend, backend, t, &dst)` on a stack view).
Under `-sm tensor` that buffer type is the **Meta** buft, whose per-device copies are only reachable through
the split state, so the copy ended in `ggml_backend_meta_buffer_set_tensor` with a NULL simple tensor:

```
GGML_ASSERT(tensor) failed  ← ggml_backend_tensor_set(NULL)
  ← ggml_backend_meta_buffer_set_tensor ← ggml_backend_tensor_copy
  ← llama_context::extract_layer_inputs ← llama_context::decode
```

This is **pre-existing and not DFlash2-specific**: the r54 guard only covered selector models, so any
DFlash drafter that requests target layer inputs (`dflash.target_layers`, i.e. every DFlash2 GGUF) would
have hit it under `-sm tensor`.  Fixed by taking the existing host fallback (the same one the allocation
failure already uses): the draft then gathers these features from the host buffers, byte-identical output.
Cost: 5 layers × 5120 × n_tokens floats per target decode batch (decode only; the prefill path is
unaffected: 2-GPU prefill with the draft is 1387 t/s vs 1203 for `-sm layer`).  *Not* done: a real
Meta-buffer device copy (a `cpy_tensor_async` on the meta backend that resolves the view chain per device);
it would remove that host trip and is a clean follow-up.

**F2 (fixed here too — it blocked the promotion gate).**  `-sm tensor` + a draft + **host-resident
experts** on the 35B-A3B Q8_0 (37.8 GB) aborted at the draft context's reserve:

```
ggml_backend_cuda_buffer_type_alloc_buffer: allocating 1280.00 MiB on device 0: cudaMalloc failed: out of memory
ggml_gallocr_reserve_n_impl: failed to allocate Meta() buffer of size 1044930688
graph_reserve: failed to allocate compute buffers
```

Mechanism (found by reading the slab layout in the `-v` log): the draft context's compute buffer is pinned
into the slab's **narrow-2** region, which is placed at the TOP of the slab's reserved VA.  The existing
placement only accepted it in the VA the creation reservation left **unmapped**, i.e.
`reserve − headroom`, and the reserve is `headroom + aux` where `aux` is the *draft-context estimate* —
whose `compute` term is a measured tier of **512 MiB** (768 above `-ub 4096`, `common/draft-reserve.cpp`).
A **tensor-split** drafter breaks that estimate: every device runs the whole draft graph, so its per-device
compute buffer measured **1280 MiB**, larger than the entire unmapped spare (0.81 GiB):

```
ggml_cuda_slab_narrow2_floor_locked: device 0: no room for a 1.25 GiB narrow-2 region above the work region
(1.25 GiB) and a 2.00 GiB arena floor in a 21.00 GiB slab (mapped 20.19 GiB); the draft compute buffer stays
on the cudaMalloc path
```

…and the cudaMalloc then cannot fit, because the slab holds the VRAM.  `GGML_CUDA_SLAB_RESERVE_MIB=16384`
worked only by accident (it enlarges the unmapped spare to `reserve − headroom`).

**Fix** (`ggml/src/ggml-cuda/ggml-cuda-slab.cu`, `ggml_cuda_slab_narrow2_alloc`): keep the preferred
placement in the unmapped spare, and when that is too small take the region out of the **arena's mapped
area** instead — the arena is the lowest-priority VRAM consumer (the r20 invariant, "the arena is what
yields").  The pin is now a two-phase operation because the eviction re-enters the slab through
`arena_free` and so must run outside `g_slab_mutex`: decide under the lock (`narrow2_pin_locked`), call
`moe_cache_evict_slab_range` for the tables in `[off, mapped)`, then commit under the lock
(`narrow2_commit_locked`) — mapping the region when it lies above `mapped`, otherwise capping the arena at
`off` (`ggml_cuda_slab_arena_limit` already returns `narrow2_off`) and dropping every `arena_free` run at or
above the new top so a later table cannot land on the draft's view.  The bytes between the new arena top
and the old mapping stay mapped but idle; that waste is exactly the estimate's shortfall and is never handed
out again.

Measured, `Qwen3.6-35B-A3B-Q8_0` + its DFlash2, `-ncmoe 20 -c 8192` (no override env):

| | before | after |
|---|---|---|
| 2 GPU | **abort** (`graph_reserve`) | acceptance 0.849, **138.6 t/s** |
| 3 GPU | **abort** | acceptance 0.849, **87.4 t/s** |

and the pre-existing behaviour is untouched when the draft *does* fit the spare (1 GPU, `-ncmoe 40`:
"narrow-2 (draft compute) pinned at [27.31, 28.06] GiB (0.75 GiB, **unmapped VA spare**)", acceptance
0.825, 98.5 t/s).  Also unchanged: the plain `-ncmoe` path (no draft → narrow-2 is never armed), the
canonical 2-GPU DFlash2 number (84.8 t/s) and `test-backend-ops` (3/3).

**F3 (nit, fixed in passing).**  `static_assert(GGML_OP_COUNT == 107, "GGML_OP_COUNT != 108")` in
`ggml/src/ggml.c` — the message named the *next* count where upstream keeps both numbers equal
(`097cf33d9` has `== 101, "GGML_OP_COUNT != 101"`); the mismatch came in with a delivery block that bumped
the count.  Now `== 108, "GGML_OP_COUNT != 108"`.

## 5. Promotion plan (needs the maintainer's decision)

Proposed split, following the "fold into the block that owns the concern" rule:

* **block 09** (Meta/iface/scheduler): `GGML_OP_ALL_GATHER` — the ggml core op, CPU/CUDA execution, the RPC
  patch bump, the split state, the boundary and the collective.  It is a Meta-backend feature; block 09 is
  where the Meta work lives.
* **block 11** (DFlash): the one-line use in `build_dflash2_selector()`, the r54 rejection removal, and the
  `extract_layer_inputs` Meta fallback (F1) — a DFlash-only path.
* **block 09** (again, with the Meta work): the F2 slab fix (`ggml_cuda_slab_narrow2_alloc`, the
  `narrow2_pin_locked`/`narrow2_commit_locked` split) — it is a slab (block 09/10) defect that a
  *tensor-split* draft's compute size exposes, and it is independent of DFlash2.
* Then: regenerate `patches/`, `release.json`, `scripts/validate-set.sh`, a `WORKLOG.md` entry, `TODO.md`
  #78 closed (and this campaign archived to `archive/work/dflash-meta-split-impl/`), `patches/README.md`
  block 09/11 notes, and — if a kill switch is wanted — one environment variable.  My recommendation:
  **no new env var** (the fallback for a user who hits trouble is `-sm layer`, documented in the block-11
  note; a knob that merely restores the old rejection has little user value).  `GREEDY-PURITY.md` needs no
  new section: the change is per-device work on identical data, and RDNA4 prefill/decode numerics outside
  the DFlash2 selector are bit-identical (proved by the prefill-logit gate above).

Open design question worth a sentence in the block note: this gathers the **whole logits row** (≈ 1 MB per
token per device) where a true distributed top-k would gather only `top_k × n_devices` candidates.  The
measured cost is not visible in the totals above (depth-16384 decode 84.5 t/s, i.e. the gather is inside the
noise of the draft step), so the simpler primitive is what shipped; a distributed top-k remains available as
a later optimisation if a longer draft block ever makes it matter.
