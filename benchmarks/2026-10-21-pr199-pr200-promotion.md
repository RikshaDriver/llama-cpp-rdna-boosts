### The pending-window guard (our change to the submitted form)

The GDN-norm fold decides twice: the skip at the `RMS_NORM` node, the emit at the gate node.  Instrumented
(`GGML_CUDA_GDN_NORM_DEBUG`, not shipped) on Flash-Next, the window is always **span 4** with a fixed
signature:

```
GDNNORMSKIP i=67 s=71 span=4: [67]RMS_NORM [68]MUL [69]MUL_MAT [70]RESHAPE [71]UNARY
GDNNORMGATE s=71 r=67 span=4
```

(repeated identically for every GDN layer).  The full chain, including the gate matmul lookup, is validated
at skip time; the only hazard is another fusion starting inside those three nodes and spanning the gate.  The
guard: while a norm is pending, no other fusion may start before its gate node, and the pending norm's own
`MUL` (dead — the gate kernel reads `xn` and `w` directly) is skipped.  The submitted form's two
`GGML_ABORT`s stay as tripwires, now unreachable rather than merely unlikely.

## Reproduce

```bash
# candidate tree
cd ~/llama.cpp && git worktree add ~/llama-pr <base> --detach
cd ~/llama-pr && git am -3 <PR patches>           # PR #199 0001, PR #200 0001-0003
BUILD_DIR=build-pr ~/bin/build-llama-rocm

# PR199 (gfx1100)
HIP_VISIBLE_DEVICES=0 ROCBLAS_USE_HIPBLASLT=0 ./build/bin/llama-bench -m <gemma4-26b-qat> \
  -p 2048 -n 0 -d 32768 -r 2 -fa on -ctk q8_0 -ctv q8_0 -t 8
GGML_CUDA_FA_RDNA3_WMMA_512=0 ./build/bin/llama-cli <same args as default> -n 200 --seed 42 --temp 0

# the KLD calibration (one base, two candidate arms)
PPL=./build/bin/llama-perplexity; C=/llm/models/wikitext-2-raw/wiki.test.raw
GGML_CUDA_FA_WMMA_256=0 $PPL -m <gemma4-26b-qat> -f $C -c 512 --chunks 40 -ngl 99 -fa on -t 8 \
    --kl-divergence-base /tmp/base-fulltile.kld
$PPL -m <gemma4-26b-qat> -f $C -c 512 --chunks 40 -ngl 99 -fa on -t 8 \
    --kl-divergence --kl-divergence-base /tmp/base-fulltile.kld
```

`--kl-divergence-base FILE` alone **writes** the file; the compare run needs `--kl-divergence` too (getting
this wrong silently overwrites the base, and it cost a run here).
