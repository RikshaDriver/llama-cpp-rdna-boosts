## What this does and does not prove
# * It proves the *pool* contains several bit-classes with wildly different cost, and that a caller who
#   picks deterministically (min index, or a validated index) gets fixed bits -- so arm G is mechanically
#   feasible without a kernel.
# * It does NOT by itself reproduce the end-to-end lottery here: `hipblasLtMatmulAlgoGetHeuristic` was
#   stable across the 10+6 standalone processes above, while the real run produced 3 logit classes in 8
#   starts.  The instability therefore sits in ROCBLAS's selection (the `getAllSolutions()` heap-ordered
#   container -- 7 different orders in 8 fresh starts, evidence/getallsolutions-order.txt), which is
#   exactly the layer arm G removes by calling hipBLASLt ourselves.
# * Timing is per-launch on a synthetic problem (20 launches, one visit): use it for the CLASS STRUCTURE
#   and the order-of-magnitude, not as a benchmark.  End-to-end prefill must still be measured
#   (llama-bench, interleaved visits) before claiming a win.
