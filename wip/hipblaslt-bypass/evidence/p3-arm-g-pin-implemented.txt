# P3 (arm G) -- a deterministic hipBLASLt solution in OUR code: implemented, deterministic, and FASTER
# gfx1201 soar, ROCm 10.1.0 (/opt/rocm-10.1.0-gfx120X), 35B-A3B Q4_K_M unless stated, one GPU job at a
# time, fresh process per sample.  Prototype patch (NOT delivery):
#   tools/experiments/hipblaslt-pin-ATTEMPT.patch   (ggml-cuda.cu +202, ggml-hip/CMakeLists.txt +7)
# It is applied to a working ~/llama.cpp, measured, and reverted after the session (same discipline as
# the arm-B attempt).
#
# WHAT IT DOES
#   ggml_cuda_mul_mat_cublas_impl(), the F32 single-matrix branch that calls cublasSgemm (rocBLAS ->
#   hipBLASLt), first tries a direct hipblasLtMatmul with ONE solution chosen from
#   hipblaslt_ext::getAllAlgos by a validated index (modexpr: m <= 64 -> 140219, else -> 140232), cached
#   per (device, dtype, m, n, k, ldc).  If the shape/plan is refused (no such index, or the launch
#   returns an error) it falls through to the rocBLAS call exactly as before.  ROCm-only
#   (GGML_HIP_HIPBLASLT_PIN, set by an optional find_package(hipblaslt) in ggml-hip/CMakeLists.txt);
#   CUDA/MUSA/SYCL/Vulkan/CPU are untouched.  Env: GGML_CUDA_HIPBLASLT_PIN=1 (default OFF, WIP),
#   GGML_CUDA_HIPBLASLT_PIN_INDEX[_LARGE|_BF16] to override a pick, GGML_CUDA_HIPBLASLT_PIN_LOG=1 to
#   print the resolved plan.  It does NOT remove hipBLASLt and does not cover BF16 (so Flash-Next is
#   untouched -- see "Non-interference").

## 4. Prefill-logit purity (issue #113 calibration) -- 35B-A3B, -c 512 --chunks 8, 1 GPU
# Each cell is `llama-perplexity --kl-divergence-base <base> --kl-divergence` against a logits base
# captured from a fresh process:
#   pinned       vs default(base)    mean KLD 0.007279 +-0.000470   same-top-p 96.618 %
#   rocblas-only vs default(base)    mean KLD 0.007271 +-0.000701   same-top-p 96.618 %   <-- same distance
#   pinned       vs rocblas-only     mean KLD 0.006757 +-0.000416   same-top-p 97.108 %
#   pinned       vs pinned           mean KLD 0.000000            same-top-p 100.000 %  (determinism control)
#   default      vs default(base)    mean KLD -0.000000           same-top-p 100.000 %  (that pair agreed)
#
# scripts/gate-prefill-logits.sh (base arm = GGML_CUDA_HIPBLASLT_PIN=0, candidate = pinned), --chunks 8:
#   dense Qwen3.8-27B Q8_0 : mean KLD 0.000001 / same-top-p 100.000 %  -> PASS (the pin is unreachable: 0
#                            intercepts, no F32 shape qualifies -- this is the "no collateral" check)
#   35B-A3B Q4_K_M         : mean KLD 0.007279 / same-top-p 96.618 %   -> FAIL (limits 0.005 / 98 %)
#
# The 35B-A3B FAIL is the LOTTERY, not the change: the arm that disables hipBLASLt (currently the
# documented determinism control) is the same distance from the same base (0.007271 vs 0.007279), and the
# pinned-vs-pinned control is exactly 0.  The tag is therefore: **this is a kernel-FAMILY switch** (as
# expected -- it changes the GEMM summation order), with a magnitude that a recorded base on the current
# lottery can no longer resolve: the class spread (0.0068-0.0073 here, 0.0035 in the #75 record) straddles
# the 0.005 gate limit, so any base recorded on an unpinned build can fail this gate by accident.  A
# delivery that ships the pin must record the prefill base ON the pinned path (then the arm is stable and
# the gate measures real changes again) -- that is a maintainer decision, not taken here.

## 5. Non-interference
# * Flash-Next GSQ-IQ3_XXS (BF16 only, 2790 hipBLASLt dispatches): the pin is F32-only, and the pin log shows
#   ZERO intercepts on a 2 GPU -sm tensor -ncmoe 48 run -> the +51 % prefill advantage hipBLASLt gives that
#   model is untouched, and so is its per-start variability (P3(i) is still the BF16 job).
# * Dense Qwen3.8-27B Q8_0: zero intercepts (no F32 GEMM with m <= 256, n >= 17, k >= 256).
# * Same-seed greedy text (35B-A3B, temp 0, seed 42, --reasoning off): base / pinned / rocblas-only produce
#   the IDENTICAL text ("The capital of France is **Paris**.").  Text is a weak instrument (see
#   FINDINGS-2026-10-21-todo-75.md §4) -- the logits-level rows above are the evidence.
#
# * ROCBLAS_USE_HIPBLASLT is not consulted on the pinned path: with the pin on, `ROCBLAS_USE_HIPBLASLT=0`
#   no longer disables hipBLASLt for these shapes.  The kill switch is GGML_CUDA_HIPBLASLT_PIN=0 (which
#   restores today's behaviour exactly).

## 6. Open items a delivery has to clear
# 1. PORTABILITY OF THE INDEX.  140219/140232 are hipBLASLt solution indices of THIS runtime (10.1.0); the
#    pool is arch- and build-specific (see §7 for what 7.14.1 does).  A delivery needs a validated pick per
#    ROCm line it ships, and a documented fallback -- the prototype's rules already degrade safely: an index
#    that is not advertised -> smallest advertised index (still deterministic); a launch that errors ->
#    refuse the shape for the rest of the process and use rocBLAS (today's behaviour).
# 2. PER-CALL COST.  One std::map lookup + mutex per pinned GEMM after the first call.  Negligible for the
#    ~60 calls/run measured here; it should be a per-context direct cache before it meets a model with
#    hundreds of F32 GEMMs.
# 3. BF16 (P3(i)).  Out of scope here: Flash-Next keeps its +51 % AND its lottery.
# 4. The prefill-logit base policy (see §4).
