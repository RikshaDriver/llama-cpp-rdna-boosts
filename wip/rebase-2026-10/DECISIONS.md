### Session-1 mechanics worth knowing for the next session

* During a rung rebase, `<<<<<<< HEAD` is **not** pure upstream: it is upstream + every already-rebased
  block.  Read the conflict in that light (e.g. block 10's "HEAD" dispatcher already contained blocks
  06-09's arms).
* A block that *moves* code (block 10 moved `ggml_cuda_try_fuse` into its own TU) cannot be resolved
  from the conflict markers.  The method that worked: rebuild the moved region by a 3-way merge with
  `base = <block-09 tree>:<old file>`, `ours = <block-10 tree>:<new file>`, `theirs = HEAD's region`,
  using `git merge-file` (0 conflicts).  Keep that tool for future rungs.
* Helper scripts written during the session: `/tmp/resolve_conflicts.py` (resolve a file by taking
  head/theirs/both per hunk), `/tmp/rewrite_fixes.py` (attribute a working-tree fix to a specific
  block commit by rewriting trees with `git commit-tree`).  If `/tmp` is gone, re-create them — they
  are cheap and they kept the per-block trees consistent.
* Logging: the new upstream CLI swallows `GGML_LOG_INFO` from the backend, so "no log line" is not
  evidence that a kernel path did not fire.  Probe with an env-gated `fprintf(stderr, ...)` + rebuild,
  or measure the path's effect (that is how the chunked-GDN A/B above was confirmed).
